# 管理端流程配置业务需求

状态：业务规则已确认，原型待调整。适用范围：职工端发帖、评论、举报与管理端内容审核、事项办理。

## 一、设计原则

流程配置按**触发事件**管理多套独立模板，不以一条流程覆盖所有内容。模板决定接收角色、处理节点和流转去向；栏目用于限定模板的适用范围。内容是否公开与事项是否办理是两个独立决定，分别记录状态和操作历史。

## 二、事件与处理规则

| 触发事件 | 内容发布或处置 | 办理业务线 |
| --- | --- | --- |
| 建言献策、心声诉求提交 | 进入人工审核，由审核人决定公开、退回修改或驳回 | 不自动生成事项；审核人同时决定是否转为办理事项。决定办理后才登记事项，进入接收角色公共待办 |
| 业务交流提交 | 未命中启用的敏感规则直接公开；命中后提交成功但暂不公开，转人工审核 | 不自动生成事项 |
| 评论提交 | 未命中启用的敏感规则直接公开；命中后提交成功但暂不公开，转人工审核 | 审核结论和评论记录关联原帖，不生成办理事项 |
| 举报提交 | 始终由指定角色人工核查，记录成立或不成立及理由 | 成立后再人工选择隐藏等处置；不自动删除原内容 |

敏感词命中后的目标规则是**提交成功、进入待审核、审核通过后才公开**，替代现有原型的“提交前直接拦截”。审核前的内容不得在职工端公开列表或评论区出现；对发起人展示待审核状态。对于确需禁止接收的特殊内容，须另行定义独立的禁止提交规则，不能混用普通敏感词命中规则。

## 三、建言献策与心声诉求

1. 职工提交后产生内容审核待办，不自动创建办理事项。审核人分别作出**公开决定**和**办理决定**；退回修改或驳回时，记录原因并通知发起人，不创建事项。
2. 审核人可以选择“仅公开”“仅内部办理”“公开并办理”或“不公开且不办理”。“仅内部办理”对公众不可见，但对发起人保留提交及办理反馈入口。涉及隐私或不适宜公开内容时，审核人须明确公开范围。
3. 决定办理时，登记唯一事项编号并进入配置的接收角色公共待办；认领后确定当前责任人，再执行分办、协办、进度更新、延期、答复复核、反馈和办结。决定不办理须记录理由。
4. 内容状态与办理状态分开保存：内容状态如待审核、已公开、未公开办理、退回、驳回、已隐藏；办理状态如未立项、待认领、办理中、待复核、已反馈、已办结。帖子状态不得再用于表达办理进度。
5. 内容审核结论触发办理线路；办理答复是否公开另由答复复核及发布动作决定，不由原帖是否公开自动推断。

## 四、模板配置

管理端“配置管理 → 流程配置”按事件展示模板列表，至少提供建言献策提交、心声诉求提交、业务交流提交、评论提交、举报提交五套模板。每套模板配置：

- 基本信息：模板名称、触发事件、适用栏目、启停状态、版本及生效时间；同一事件和栏目组合不得同时匹配多套已发布模板。未匹配时采用明确的默认规则或阻止配置发布，不允许静默绕过审核。
- 接收与节点：接收角色及公共待办、可增删的处理节点、节点责任角色、处理动作、通过/退回去向、条件分支、复核角色、办理时限及超时兜底。节点删除不得使已发布版本中的运行任务丢失。
- 转办：限定可转办角色、人员和组织范围；发起转办后原责任人继续负责，接收方确认时才转移责任。拒绝或超时则退回原责任人并留痕；禁止转给无数据权限者。
- 异常与兜底：退回修改、驳回、延期、接收人不可用、无人认领、超时、重复触发等情形均须有去向和提醒对象；超时不得自动公开、自动认定举报成立或自动办结。

## 五、模板版本与校验

模板按“编辑草稿 → 路径检查 → 模拟运行 → 发布”管理。路径检查至少验证事件匹配唯一、节点可达、各分支有终点、退回去向有效、责任角色存在且具备数据范围、超时兜底完整。模拟运行覆盖未命中/命中敏感规则、审核通过/退回/驳回、公开/办理组合、转办接受/拒绝/超时和举报成立/不成立。

发布产生不可改写的新版本。新提交的事件使用生效版本；已发起任务固定使用启动时的模板版本，不因后续修改改变节点或责任。停用模板前需检查替代模板或默认处理路径，不影响已运行任务。

## 六、权限、记录与闭环

平台管理员维护和发布模板；被授权的内容管理员、分办管理员、承办角色按节点权限操作，领导视图只读。所有认领、转办申请与确认、内容审核结论、办理决定、答复复核、举报结论、隐藏及恢复均记录操作者、时间、理由、前后状态、模板版本和关联内容/事项编号。匿名身份保持独立权限控制，普通流程日志不直接暴露真实身份。

职工端可查询自己的发帖、评论及举报处理结果；公开内容在审核通过后展示，办理事项的进展和反馈按授权范围回传。管理端可从原帖进入审核记录及关联事项，从事项回看来源帖和答复，从举报回看被举报内容及最终处置，形成双向关联。

## 七、原型调整边界

当前原型的流程配置仍按“建言献策/心声诉求栏目 + 流转/审批两页签”展示，职工端敏感词命中仍会阻止提交。本文件是目标需求，不代表这些行为已实现。下一步原型需优先调整：事件模板列表和编辑器、人工审核的公开/办理双决定、独立状态字段、敏感命中待审核、公共待办认领与转办确认、版本检查和模拟入口；保留现有业务数据时应做状态迁移，避免历史帖子或事项丢失。
