# 承办接收与转办闭环

## 业务规则

- 建言献策、心声诉求均进入事项办理候选，不因敏感词命中而取消办理。
- 内容公开状态与事项办理状态分离；帖子可以暂不公开，但仍可登记、分办和办理。
- 登记事项后进入“待承办确认”，并指定初始承办部门和承办人。
- 初始承办人必须点击“确认办理”后，事项才进入“办理中”。
- 初始承办人可以发起转办；转办后事项进入“转办待接收”，目标承办人点击“接收办理”后，责任部门和责任人正式变更。
- 未接收的承办人不能更新进度、保存答复草稿、申请延期或提交正式答复。
- 只有当前最终承办人可以更新进度、编辑答复和提交正式答复；协办部门仅提交协同意见和附件。
- 管理员可以查看全量事项、转办记录、接收记录和复核结果，但不能替代承办人完成接收。

## 状态

`待登记` -> `待承办确认` -> `办理中` -> `待复核` -> `已反馈` -> `已办结`

转办支线为：`办理中` -> `转办待接收` -> `办理中`。退回复核为：`待复核` -> `退回修改`（页面展示） -> `办理中`。

## 原型边界

承办人使用现有唯一登录页和同一套承办管理页面；浏览器本地数据模拟部门、账号和流转。正式系统仍需由服务端校验角色、账号状态和数据范围。
