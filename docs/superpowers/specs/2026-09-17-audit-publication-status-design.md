# 审核状态与发布状态拆分设计

## 目标

信息内容审核只产生审核结果，不自动代表内容已发布。管理端和职工端都要同时展示审核状态与发布状态。

## 状态模型

- 审核状态：待审核、审核通过、已驳回。
- 发布状态：未发布、已发布、私密发布。
- 审核通过后，内容默认保持未发布；管理人员再执行“发布”或“私密发布”。
- 建言献策和心声诉求在审核通过后照常生成待分办事项，发布状态仍独立。

## 界面与文案

- 审核按钮统一为“审核通过”，不再使用“审核通过并发布”。
- 已通过且未发布的内容提供“发布”和“私密发布”操作。
- 职工端业务交流进度为“待审核 → 审核通过 → 发布状态”，当前状态同时显示审核结果与发布结果。

## 验收标准

1. 审核通过后，记录显示“审核通过 + 未发布”。
2. 点击“发布”后只改发布状态为“已发布”，审核结果不变。
3. 点击“私密发布”后只改发布状态为“私密发布”。
4. 职工端业务交流不再把“审核通过”等同于“已发布”。
