# 事项分办职责收敛与催办设计

## 目标

收敛管理端“事项办理”模块：删除独立“公开与归档”页面；分办阶段只配置责任、时限和要求；答复方式在答复审核时决定；已分办事项支持管理端催办。

## 页面与流程

- “事项办理”下仅保留“事项分办”。
- “已办结”仍保留在“事项分办”的页签中，因此删除“公开与归档”不丢失查询入口。
- 分办表单移除“答复方式”，分办保存不再写入该字段。
- 答复审核弹窗保留“反馈方式”，审核人员在通过答复时选择“公开答复”或“私密回复”。
- 办理中详情不展示尚未确定的答复方式；待答复审核和已办结详情可展示。

## 催办

- “已分办”页签每行在“查看详情”旁增加“催办”。
- 催办弹窗展示事项、当前办理人、截止日期，并提供必填催办说明。
- 确认后：事项写入 `courted`、`courtedAt`、`courtedReason`；流转记录追加催办事件；当前办理人的通知队列新增催办消息；操作审计留痕。
- 催办不改变事项状态，不调整办理期限，也不影响答复审核和办结分类。
- 已催办事项状态辅助显示“已催办”，按钮改为“再次催办”。

## 验收标准

1. 导航中不存在“公开与归档”，旧路由不再暴露对应页面。
2. 分办弹窗无“答复方式”，确认分办仍可正常完成。
3. 只有答复审核弹窗可选择答复方式。
4. 已分办列表可发起催办；提交后列表、流转记录和承办消息均有反馈。
5. 催办后事项仍位于“已分办”页签，四页签数量互斥关系不变。
